# Agent Instructions

This document is for Codex and similar coding agents. The goal is to generate an `assignments.js` file that this extension can execute safely.

## Mission

Given a current Chrome bookmark source and a user request, produce `assignments.js`.

Do not directly rewrite Chrome's `Bookmarks` file as the final sync strategy. The final write path should be Chrome's `chrome.bookmarks` API through this extension.

## Privacy

Treat bookmarks as private data.

- Do not commit real `assignments.js`.
- Do not paste large private bookmark lists into public issues, pull request descriptions, or READMEs.
- Keep generated reports local unless the user asks otherwise.
- Commit only `assignments.example.js`, synthetic examples, and documentation.

## Input Sources

Possible sources:

- A local Chrome `Bookmarks` JSON file, read as analysis input only.
- A user-supplied copy of a `Bookmarks` JSON file.
- A template generated by the extension's `Generate Template` button.

Avoid using Chrome-exported HTML as the only source because exported HTML does not reliably preserve Chrome bookmark IDs.

## Required Output

Create:

```text
assignments.js
```

It must define:

```js
globalThis.CODEX_BOOKMARK_TARGET_NAMES = [
  "Exact Target Folder Name"
];

globalThis.CODEX_BOOKMARK_ASSIGNMENTS = {
  "Exact Target Folder Name": {
    categoryOrder: [],
    subcategoryOrder: {},
    byId: {}
  }
};
```

## Generation Workflow

1. Find each requested target folder.
2. Recursively collect URL bookmarks under each target folder.
3. Preserve each bookmark's `id`, title, URL, and original folder path when available.
4. Classify each bookmark.
5. Build `categoryOrder`, `subcategoryOrder`, and `byId`.
6. Write `assignments.js`.
7. Tell the user to reload the unpacked extension and run `Dry Run`.

## Classification Rules

Unless the user says otherwise:

1. Use the bookmark title as the primary classification signal.
2. Use the original folder path as the secondary signal.
3. Use URL/domain as the tertiary signal.
4. Preserve every URL bookmark under each target folder.
5. Do not include folder nodes in `byId`.
6. If uncertain, place the bookmark under `99 Unclassified/Needs Review`.

## Mapping Rules

Every URL bookmark under a target folder must appear exactly once:

```js
byId: {
  "123": ["01 Group A", "Bucket A", 0]
}
```

The tuple means:

```text
[categoryFolderName, subcategoryFolderName, orderWithinSubcategory]
```

Rules:

- `id` must be a string.
- `categoryFolderName` must be a string.
- `subcategoryFolderName` must be a string.
- `orderWithinSubcategory` must be a non-negative integer.
- The order number only needs to be unique within the same target/category/subcategory.

## Validation Before User Runs Extension

Before handing off to the user, validate by inspection:

1. Every configured target folder is represented.
2. Every URL bookmark under every target folder has exactly one `byId` entry.
3. No `byId` entry points to a folder node.
4. No duplicate bookmark IDs appear across target folders.
5. `categoryOrder` includes every category used in `byId`.
6. `subcategoryOrder[category]` includes every subcategory used under that category.
7. Counts are preserved.

The extension's `Dry Run` is still required because Chrome Sync or another device may have changed IDs or structure after the source was read.

## Human Handoff

Tell the user:

1. Back up or export bookmarks first.
2. Load the folder as an unpacked extension in `chrome://extensions`.
3. Click `Dry Run`.
4. Run only if Dry Run reports an exact match.
5. Keep Chrome open for a few minutes after completion so Sync can upload changes.
6. Check another device before deleting backups.
